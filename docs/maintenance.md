# 维护与验证

日期：2026-10-17。只维护当前实际运行的 `web/`，不依赖研究工作区里的相邻旧版本。

## 改动入口

| 想改什么 | 入口 | 必须留意 |
|---|---|---|
| 题目和选项 | `web/questions.js` | 每次一题、保留不确定；与推荐输入值一致 |
| 条件路由与解释 | `web/engine.js` | 空间和预算优先，但不是按预算花光；不作尺寸/预算自动验收 |
| 参数/价格/来源 | `web/data.js` | 原来源和原日期；单机套装分开；未知不填0 |
| 交互/结果页 | `web/app-v04.js` | 返回问题后保留选择，修改后重新算结果 |
| 全系/详情 | `web/pages.js` | 能力路线不是年份/改装路径，新品不猜参数 |
| 本地笔记 | `content/notes.json`；查询程序为`web/notes.js` | 数据CC BY-NC 4.0、程序MIT；保留作者经验和朋友案例边界，不伪造平台直达能力 |
| 欢迎与声音 | `web/welcome.js` | 用户点按后发声，离页/隐藏停止，无声降级 |

## 修改数据

把资料按字段记录为官方正文、官方摘录、历史沿用、用户反馈、经验解释或未核。查不到的字段保持未知。官网名称或页面存在，不等于已读取相应参数。

价格必须记录配置、日期、地区、币种、来源和未核条件。不能用A1单机价与X2D AMS套装价直接排“同配置性价比”；不能把618数据静默改成双十一价。需要改变预算路由时，先补同口径报价，再修改规则和解释。

只有五轮选项，无法精确覆盖全部模型、材料、桌面和预算组合。更换固定路由为动态筛选是一项独立产品改动；不要为了“智能”增加没有证据的匹配百分比。

## 软件验证

按 README 顺序运行 build、validate、tests、package。打包后逐项核验ZIP内文件哈希与当前dist。构建必须从白名单产生干净dist，校验不应只相信过时manifest。

重点保留：

- 高预算小摆件仍可比较有价值的高配；卧室优先换位置。
- 有明确上限且报价超限，不能继续写成预算内首选。
- 手机/可乐类比不能批准模型尺寸；机身外形不等于整套占地。
- 软料与送料、主辅喷嘴分开核；颜色做法不创造材料兼容性。
- 新品传闻不参与正常推荐；未知项有下一步，不靠身份决定机型。

浏览器走查至少包括320×568与390×844：首页、五轮、两种结果、修改答案、笔记返回、全系与新品。现代浏览器结果只记为开发证据。发布前还需对同一个ZIP在平台模拟器、Android和iOS验证；没有执行就记待验证。

## 两种构建的素材边界

公开版使用本轮原创通用结构SVG，完整clone即可构建。本地品牌版可按明确命令加载 `private-assets/` 中九张既有机器PNG。该目录不入Git、不入公开源码ZIP，构建品牌包也不代表新增了公开再分发许可。品牌版只用于用户既有平台项目的本地候选，实际上传发布另行执行。
